# 《消费计算统一结果自动化测试报告》

- 项目：frontend-vue3-base
- 测试日期：2026-07-22
- Node.js：v24.16.0
- 测试框架：Node.js 内置 `node:test`
- 模块加载：项目已有 esbuild，仅用于在测试进程内加载业务 ES 模块
- Storage：内存模拟 `uni.getStorageSync`、`uni.setStorageSync`、`uni.removeStorageSync`
- 执行命令：`node --test tests/*.test.js`

本次未修改业务代码，测试数据没有写入微信开发者工具或真实小程序 Storage。

## 2. 测试结果

| 案例 | 结果 | 说明 |
|---|---|---|
| 无活动消费 | 通过 | 100元原价消费，折扣金额0，应付100 |
| 单个消费折扣活动 | 通过 | 100元使用0.8折扣率，折扣20，应付80 |

| 删除活动 | 通过 | 删除8折活动后无生效活动，100元恢复原价 |
| 多活动优先级 | 通过 | priority数字越大越优先；选择priority=20的活动B，支付70 |
| 消费记录一致性 | 通过 | 页面、弹窗、实际扣款和记录均为80；成功页参数来源为同一计算结果 |

汇总：6项通过，0项失败，0项跳过。

## 3. 一致性验证

测试确认正常页面流程使用同一 `calculation` 对象：

```text
calculateConsumption()
→ 页面试算
→ 确认弹窗
→ consume({ calculation })
→ 余额扣减
→ 消费记录
→ result.calculation.paidAmount
→ 成功页
```

100元8折测试结果：

| 环节 | 金额 |
|---|---:|
| 页面试算 | 80 |
| 确认弹窗 | 80 |
| 实际扣款 | 80 |
| 消费记录 | 80 |
| 成功页传参 | 80 |

## 5. 风险分析

1. 当前自动化测试属于 Service 集成测试与页面源码契约测试，没有启动微信开发者工具执行真实组件点击。
2. 成功页一致性通过源码契约验证：消费页使用 `result.calculation.paidAmount` 传参，成功页读取同一 `options.amount`。建议继续执行配套微信端人工清单。
3. 项目没有 `npm test` 脚本。为遵守本次“只新增测试和报告、不修改业务代码”的限制，测试使用 `node --test tests/*.test.js` 执行；后续可单独安排任务在 package.json 中加入测试脚本。
4. 测试依赖项目现有的 esbuild 间接依赖。如果后续构建工具调整，应考虑引入正式测试框架并固定测试依赖。
